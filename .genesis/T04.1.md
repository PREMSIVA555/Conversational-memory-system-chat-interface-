## What changed

Owned card enquiries now distinguish daily limit, credit limit, available credit and outstanding. Debit credit fields are null and render as not applicable. Two owned cards ending in the same digits require clarification using a full card reference. Card status and transaction status remain explicit. Pending/declined amounts are not labeled posted spend, and missing reasons stay unknown. No PAN/CVV, settings mutations or money movement.

Transactions use inclusive UTC date ranges, timestamp/ID ordering and signed owner/card/range/status/page-size/version-bound expiring cursors. Load next page submits a fresh durable question. Conversation and pending labels show “next page” instead of the opaque cursor; the original accepted payload remains available for replay. Existing tenant/session checks, source checking and deterministic Money rendering apply to card tools. The model selects registered read tools; it does not supply authoritative amounts.

Authority: `.genesis/sources/P04_SOURCE.json`; SPEC07, INV02, INV07, INV08. Original PLAN_READER.html SHA256 remains `9f59fb49a54ea305387465fb606deca567d8118d7e296f7edee8605559ba70fd`. Additive migration0025; migrations0001–0024 are preserved. Card rollout is `BANK_CARDS_ENABLED`, default false, enabled only in the configured local demo and explicit private fixtures.

## How to check locally

Open https://localhost:3443/ and sign in with the existing customer-a or customer-b credentials. Create or select a conversation, then use the Account and card enquiries panel.

1. As customer-a, ask “Show my cards ending 1111.” Expect two owned choices, debit and credit; do not choose a card from suffix alone.
2. Ask “Show card details for 952c34da-d282-52f4-980d-b3c32545c937.” Expect daily limit INR1500.00, active debit, and credit fields not applicable.
3. Ask “Show card details for c01dd160-ca56-5853-965a-bba60f7dca28.” Expect daily INR2500.00, credit limit INR500000.00, available credit INR480000.00 and outstanding INR20000.00. These are distinct fields.
4. Ask “Show transactions for card c01dd160-ca56-5853-965a-bba60f7dca28 with page size 2.” Use Load next page. Four synthetic rows exist: declined -INR7.00, pending INR0.00, posted INR1250.00, reversed -INR0.01. Reasons are unknown. The default recent date range includes the demo rows seeded one day before rollout.
5. As customer-b, card 1fba3089-3ecc-5bce-94fb-9ecedbaa0b84 is owned; customer-a’s card references must reveal no card information. Customer-b has one synthetic USD credit card.
6. A request to increase a limit or change card settings must not change the bank. Existing account balance enquiries should still work.

The demo amounts intentionally differ from the extreme-value private test fixture. Demo seed details and actual runtime owner readback are in `.genesis/evidence/T04.1-demo-cards.json`. No existing account rows were changed by the migration/seed. The original81-row legacy snapshot is unchanged; see preservation evidence.
