## Implementation to review

The enquiry follows a fixed, bounded control-flow graph: claim the internal run, check model capability, reserve and request a plan, validate the registered read and its arguments, reserve the bank read, collect typed evidence, check draft claims, render the answer, revalidate the session and publish only for the current generation.

The model can select only account listing, account reading, transaction history, clarification or unsupported. It cannot supply customer identity, SQL, mutations or confirmation authority. A requested account reference must occur in the user request and pass the existing owned provider. Multiple accounts require selection. Current/available balances and transaction amounts/status/dates come from fresh authorized PostgreSQL evidence. Free model prose and unverified numeric drafts never become financial output. Semantic memory is deliberately excluded from bank authority; tests seed actual competing P02 memory to check that boundary.

| Limit | Contract |
|---|---|
| Model calls | At most3 across a logical run, including repairs/reclaimed computation |
| Repair calls | At most1, included in model count |
| Tool calls | At most2, including a retry |
| Common calls | At most6 |
| Run work deadline | Default10seconds, trusted constructor maximum30seconds; persisted and not renewed |
| Per model dispatch | At most10seconds, further reduced by remaining run deadline |
| Per tool dispatch | At most2seconds, further reduced by remaining run deadline |

Reservations commit before dispatch. Failed/duplicate computation consumes capacity. Attempt rows retain reported usage/model identity; absent usage stays unavailable, and failed cost is unknown. Installed LiteLLM metadata checks JSON response-format support; unknown/incapable models fail closed. Required JSON parameters cannot be silently dropped; transport retries are disabled. These checks do not certify a live provider/model, and acceptance uses labeled scripted raw transport responses.

The work deadline includes capability lookup. Cold metadata is awaited asynchronously under the remaining deadline. On cancellation a background import may finish later; no model transport is dispatched by that abandoned lookup. Authentication/SQL bookkeeping and response delivery have bounded infrastructure overhead; measured end-to-end HTTP duration is not claimed to equal the logical work allowance exactly.

Internal run binding uses the exact request string, customer, session and run UUID. Exact duplicate completed runs return their original result without a new read; changed text, including whitespace, conflicts. This is not semantic normalization or public turn idempotency. Public API canonical-operation fingerprints, durable accepted turns, SSE and UI recovery remain T03.3.
