# T05.1 behavioral verification contract

Use only this contract, your own test inputs and public operator outputs. Do not read implementation, test, fixture or operator source, previous chat or maker results. This is instructional isolation, not an OS sandbox.

Requirement: SPEC10 / INV05 / INV24. An immutable normalized support proposal belongs to one authenticated customer, one login session and one accepted source question. It has version, payload hash and expiry. Exact preview is returned. Editing cancels the old proposal and creates a new ID/version atomically. Concurrent initial drafts or edits cannot produce two pending previews. Owner A's second session A2 and customer B cannot access or act on A's draft. CSRF and Origin apply to every mutation. Wrong versions/hashes, edited, cancelled or expired previews cannot confirm. No model plan may confirm or create a case. Valid preview confirmation currently returns 503 because the atomic case writer belongs to T05.2; do not count this as successful execution. No banking data changes. Erasing the source prevents serving/reusing its preview.

Execute from `D:/Projects/Banking Assistant/banking-memory-agent`:
`.venv/Scripts/python.exe scripts/p051_probe.py` with one JSON stdin document `{ "steps": [...] }`. Each invocation creates its own guarded private PostgreSQL 16 database and Redis 7 namespace. Real HTTP routes and persistence run; sessions are issued by the existing server session service (OIDC login is not exercised). Workers are paused; there are no application model completions. Never read private configuration or print credentials.

Operations (default actor A; A2 is a different valid login of A; B is another customer):
- `turn`: optional text, `save: "t"`; returns HTTP status/body with turn_id.
- `draft`: body `{source_turn_id:"$t.turn_id",topic:"general",resource_id:null,summary:"Synthetic issue"}`, optional `save:"p"`.
- `get`: id `"$p.id"`.
- `latest`: turn_id `"$t.turn_id"`.
- `edit`: id plus body `{version:"$p.version",payload_hash:"$p.payload_hash",draft:{source_turn_id:"$t.turn_id",topic:"general",summary:"Revised synthetic issue"}}`, optional save.
- `cancel` or `confirm`: id and body `{version:"$p.version",payload_hash:"$p.payload_hash"}`.
- `expire`: id. Test-only clock fault sets that preview into the past, guarded private DB only.
- `revoke`: actor. Invalidates that actor session.
- `erase`: turn_id. Executes source erasure through the authenticated API.
- `parallel`: steps array for simultaneous operations. Do not reference sibling outputs.
- `oracle`: returns proposal IDs/source/version/status/hash, bank-data preservation and matched Docker identities. Case table is absent in this slice.
- `model_plan`: body `{tool:"confirm_support",args:{}}` returns accepted true/false for registry schema validation; not a live model call.

`actor`, `save` and `headers` may accompany applicable operations. Headers override defaults for CSRF/Origin negatives, e.g. `{"X-CSRF-Token":""}` or `{"Origin":"https://foreign.invalid"}`. Each saved value is the HTTP response body. `$name.field` references a saved value; predefined `$account_a`, `$account_b`, `$card_a`, `$card_b`, `$loan_a`, `$loan_b` are synthetic full resource UUIDs. Non-general topics require the corresponding owned resource. General requests reject resource IDs. Extra identity/confirmation fields must fail validation.
