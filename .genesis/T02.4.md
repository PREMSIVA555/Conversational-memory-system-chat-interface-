## Implemented behavior

- Authenticated context GET/PUT uses customer/session/conversation keys, bounded canonical selections, expected-version conflicts and 30-minute expiry. Version watermarks survive expiry to prevent stale-write ABA collisions. Canonical selectable resources in this slice are owned conversations; bank accounts/products are not implemented.
- Authenticated optional history APIs create source events and provenance-linked memory, summary, vector, cache and checkpoint record kinds. Enabled retrieval is bounded lexical history and explicitly not current bank truth. All five kinds are governed PostgreSQL records; their names do not claim five external storage engines. Semantic embeddings are disabled without a provider.
- Forgetting blocks serving and scrubs active source payload, derivative content, preferences, proposals, source spans, queued metadata and actual consumer checkpoints in the same transaction before success. Source fencing and retained minimal ordering tokens prevent stale worker/client replay from resurrecting content. Erasing an older source preserves a newer preference.
- Erasure reports active-store cleanup separately from retained quarantine snapshots, unconfigured external providers and retained synthetic published evidence. Redis contains authentication sessions, not memory content. Local active-row cleanup does not claim forensic media wiping.
- A restore check imports the retained pre-erasure JSON fixture into a transaction-local PostgreSQL quarantine table, applies an erasure ledger outside that fixture, checks restored/scrubbed/content counts, and keeps normal serving blocked. This is not a full database recovery or production backup drill. Runtime roles cannot directly read raw memory/backup tables.
- Retention declares purpose/owner/bounds. Context content expires after 30 minutes; local quarantine backups expire after 24 hours and are removed on authenticated retention requests. This is request-triggered cleanup, not an always-on deletion daemon or exact physical-media deadline. No production backup/provider deletion is asserted.

API-only scope: existing preference UI remains available; this task does not add a context/history/forgetting UI or integrate financial chat responses. T02.5 writer cutover is untouched.
