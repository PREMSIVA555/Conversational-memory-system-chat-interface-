## Behavioral requirements

1. A real authenticated workspace turn can be the source of a preview. Source and product must belong to the accepting customer and login. Another login of the same customer cannot reuse it.
2. Owned account/card/loan discovery supplies internal IDs; users need not type them. Preview responses include `resource_label` from the currently owned product: existing name, and real kind/last-four for cards. This label is outside the immutable `payload`/hash.
3. Draft payload is `{source_turn_id, topic, resource_id, summary}`. General requires null resource. Other topics require a canonical owned UUID. Text is NFC, newline-normalized and trimmed, then served exactly; markup remains text. Client identity and unexpected fields are rejected.
4. Create yields version1. Edit requires exact version/hash, atomically cancels the old row and creates a different immutable row/version. Changing source, stale binding and concurrent losing edits must not mutate an accepted preview.
5. Cancel requires exact binding. Expired/cancelled/old edited previews cannot execute. Valid confirm returns503/unavailable, never a case or success. There is no case writer here, and model tools cannot confirm.
6. Ownership/session, CSRF/Origin and least-privilege boundaries remain enforced. Resource labels must not disclose foreign products. Logout/revocation invalidates further access. Source erasure prevents serving and removes dependent preview text.
7. Verify API/persistence races (including concurrent create/edit), malformed bodies, product kinds, stale hash/version, expiry, erasure and revoked sessions. Report actual outcomes and retained failures honestly.

Command: Python `scripts/p051_probe.py` with JSON stdin `{"steps":[...]}`. Set PYTHONUTF8=1 and LITELLM_LOCAL_MODEL_COST_MAP=True. Output is `{"results":[...],"oracle":...}`. Real HTTP/server-issued sessions and private manifest-guarded PostgreSQL16/Redis7 test databases are used, not the ordinary demo. A/B are different customers; A2 is another login of A. No real OIDC/browser certification is implied by this operator.

HTTP results have `status` and `body`. Add `save:"name"` to retain the response body. Strings `$name.field` resolve saved values, including list indices such as `$products.items.0.id`. Predefined owned references: `$account_a`, `$account_b`, `$card_a`, `$card_b`, `$loan_a`, `$loan_b`.

- `{"op":"workspace_products","kind":"account","save":"products"}` discovers only A's products. `actor` can select A2/B on any request.
- `{"op":"workspace_turn","text":"View this account","fields":{"action":"balance","instructions":{"language":"en","format":"concise"},"resource_selection":{"kind":"account","id":"$products.items.0.id","version":"$products.items.0.source.version"}},"save":"t"}` prepares the login's automatic chat, accepts the actual workspace message, runs its worker once, and returns the public turn with result (normally HTTP200). Other direct actions: card_details / loan_details, with corresponding products and kind. A local greeting `text:"Hi"` is also supported. Use only local actions; arbitrary/explanation text is not needed.
- `{"op":"turn","text":"Synthetic support question","save":"t"}` accepts a legacy current-session question (HTTP202); this too is a valid source. Its worker remains paused.
- `{"op":"draft","body":{"source_turn_id":"$t.turn_id","topic":"general","resource_id":null,"summary":"Synthetic issue"},"save":"p"}` POSTs the preview.
- `{"op":"get","id":"$p.id"}` / `{"op":"latest","turn_id":"$t.turn_id"}` GET saved state.
- `{"op":"edit","id":"$p.id","body":{"version":"$p.version","payload_hash":"$p.payload_hash","draft":{"source_turn_id":"$t.turn_id","topic":"account","resource_id":"$account_a","summary":"Revised issue"}},"save":"p2"}` creates the next immutable version.
- `cancel` / `confirm` use `id` and `body:{version,payload_hash}`. Confirm intentionally fails closed with503 for a valid preview.
- `{"op":"parallel","steps":[...]}` executes steps concurrently; reference only previously saved results inside the race.
- `headers` overrides request headers; e.g. empty X-CSRF-Token / wrong Origin for negatives.
- `{"op":"expire","id":"$p.id"}` injects a test clock fault only in the guarded trial database; no application capability or ordinary-demo mutation is provided.
- `{"op":"erase","turn_id":"$t.turn_id"}` invokes authenticated source erasure through the actual API.
- `{"op":"revoke","actor":"A"}` revokes that test login.
- `{"op":"model_plan","body":{"tool":"confirm_support","args":{}}}` validates the closed model tool registry without a model request.
- `{"op":"oracle"}` returns proposal ID/source/version/status/hash rows, `bank_data_unchanged`, `case_table`, `model_calls` and actual matched container identity. Do not call assertions unique end-to-end scenarios. Preserve fault limitations and source-independence details in the report.
