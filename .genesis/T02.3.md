## What changed

- `api/preferences.py` exposes authenticated exact reads, manual edits and preference-only capture. Strict request models reject extra identity/source fields; mutations retain the existing session, CSRF and Origin checks. Foreign conversations return 404.
- `store/preference_grammar.py` matches a whole, explicit user instruction from a declared grammar. `store/banking_preferences.py` resolves exact values and source-ordered overlays. Defaults are English and concise; higher scopes win even when a lower-scope event is newer. Tombstones retain ordering watermarks so older pending values cannot reappear.
- Additive migrations 0007–0011 add session-bound proposals, typed acceptance, a source-validated receipt-gated handler, truthful dead-letter status, closed proposal shapes and bounded recovery. Installed migrations were kept immutable. Manual acceptance performs CAS, source/outbox creation, receipt, projection and terminal result in one transaction; competing manual edits cannot both reserve the same version while waiting for a worker.
- The typed worker obtains its receipt before applying projections in the same fenced transaction. A worker cannot replace the accepted proposal with another value, use the old projection primitive for a typed source, or bypass the typed handler through generic completion.
- The preference panel supports language/format settings in global or conversation scope, reset tombstones, a preference instruction box, effective values/scopes/status, recent requests and a clearly labeled settings preview. The preview is a sample, not a banking answer. Client drafts retain the version originally shown; background polling cannot silently advance a manual edit's expected version.
- A current-response preview requires its explicit source event ID in the current session. It is cleared on a new request, scope/conversation change or reload and never becomes a global setting. Customer/CSRF keyed UI instances and abort/generation guards prevent old responses updating a different session.
- Unknown network outcomes retain the exact request body and client event ID. Retry confirms that same request; new writes remain disabled until it resolves. Accepted messages point to the current processing status instead of retaining a stale Pending claim.

The bounded grammar supports `Always reply in Hindi/English`, `Always be concise/detailed`, `Reply in Hindi/English for this conversation/response`, and `Be concise/detailed for this conversation/response`. Conversation and response instructions require an owned active conversation. Optional terminal punctuation and case differences are accepted. Quoted, historical, third-party, assistant/retrieved and compound text fails closed; there is no general natural-language or model-based extraction claim.

## How to check it yourself

1. Open `https://localhost:3443/`, sign in, and find **Response preferences**.
2. Choose **All conversations**, save English, and reload. It should remain Saved.
3. Create/select a conversation, choose **This conversation**, and save Hindi. It should override global English.
4. Enter `Reply in English for this response` and apply it. The sample should use English with a temporary scope. Reload/select the conversation again; its saved Hindi should remain.
5. Enter a third-party statement such as `My mother says Always reply in English`. It should fail without changing saved settings.
