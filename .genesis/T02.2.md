## What changed

`jobs/banking_consumer.py` provides bounded dispatcher claims, lease ownership, heartbeat, source reads, checkpointing, transactional completion, classified failure and durable outcome lookup. It uses the allowlisted `acceptance.record` v1 handler: its local effect records a small server-derived processing result. This is the reusable consumer foundation; it does not extract or apply preferences.

Additive migrations 0004–0006 add `local_operations`, `consumer_checkpoints`, unique `consumer_terminal_events`, restricted functions and retry/dead-letter state. Dispatcher gets metadata-only claim access; worker/runtime cannot directly mutate these tables. Privileged functions use fixed search paths with PUBLIC execution revoked. Global job enumeration is confined to the migration owner's outbox/terminal policies and the restricted dispatcher function; customer source and operation reads still require explicit ownership checks.

The completion transaction obtains the unique handler receipt with `INSERT ... ON CONFLICT DO NOTHING RETURNING` before the local effect. Receipt, local result, terminal event and completion commit together or roll back together. Publication and reclaim lock the same outbox row. Ownership generation and actual wall-clock expiry are checked after lock waits and after potentially blocking publication writes. A replaced or expired worker cannot publish through these functions. Unknown commit outcomes reconcile the same event; an unknown result never authorizes a new logical event.

Server-side claims allow batches of 1–32 and leases of 1–60 seconds. Attempts are limited to three. Classified transient failures back off; permanent/unsupported work and exhausted attempts become visible dead letters. Fixed-label counters record source reads and duplicate suppression without customer labels.
