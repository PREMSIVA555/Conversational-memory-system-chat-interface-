## Supported input boundary and manual checks

Direct policy requests accept one literal locale tag (`de-DE`), one scope (`scope business`, or retail/business/corporate/wholesale), and one timezone-aware ISO timestamp (`at 2025-06-01T00:00:00Z`). Product must be explicit, for example `credit card`. Omitted model arguments are bound to those user constraints. Contradictory model arguments clarify; multiple/conflicting values, quoted/negated/indirect constraints, incomplete timestamps and recognized unsupported date syntax clarify rather than select a default. This is a conservative grammar, not general natural-language applicability extraction. Without explicit constraints, the existing retail and en-IN/hi-IN defaults remain.

After starting the updated API, open https://localhost:3443/ and use an existing demo login/conversation. Try “Explain credit card annual fee de-DE at 2026-06-01T00:00:00Z”: expect no applicable evidence (or a clarification if the model contradicts the question), never the en-IN rule. Try “Explain credit card annual fee scope business at 2026-06-01T00:00:00Z” with the same expectation. Try multiple locales: expect clarification. A normal “Explain credit card annual fee at 2026-06-01T00:00:00Z” remains a positive control with exact synthetic money and citations. Historical questions depend on the installed catalogue; no new policy is invented.

Privacy checks use synthetic data only. The local installed Presidio/spaCy English pipeline detects PERSON and the existing identifier classes, reinforced for phone/SSN/card formats and explicit name labels.
